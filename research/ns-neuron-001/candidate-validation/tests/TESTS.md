# Integration test record

The 194 inherited tests passed on a new copy of the recovered release. All 214 tests passed on a separate new copy of candidate 0.3.0a1+ns.neuron.1. The 20 additions comprise 15 neuron-probe tests and five integration CLI tests. No tests were skipped. Each invocation used Python 3.12.14, the 39-package reference environment, the documented unittest discovery command and the offline seccomp launcher. Source and working-copy inventories were identical before and after these suite runs.

The first recovered run also reported 194 passing tests in its raw log. The initial per-case parser omitted the outcome for one test with a two-line description, producing 193 JSON rows. That receipt and log are preserved in `recovered-001`. A second run on a new copy with the corrected parser produced all 194 JSON rows in `recovered-002`. The candidate case receipt contains 214 rows.

The separate package test built a wheel from a further disposable candidate copy, installed it offline in a clean venv with the reference dependencies and invoked the installed executable outside the source tree. The four protocol, discovery, selection and result JSON files matched the standalone pinned-model run byte for byte. The CLI also verified the manifest digest emitted by the installed study, and its 19 package source receipts matched the candidate. Commands, outputs and raw study artifacts are in `wheel-001`.

The recovered release contained 90 files. The original ZIP verified against its owner-provided digest, and every recovered file matched its corresponding ZIP member. All 44 members comprising the four historical evidence trees, validation record and original bundle inventory matched bytes in the candidate. The candidate preserves the earlier bundle inventory in `historical/v0.3.0a1-bundle-inventory.json`. The five changed inherited files and all per-file digests are listed in `candidate-history.json`.

The wheel and ZIP digests in these receipts identify artifacts from the original review. This publication includes their build and verification records, the tested source trees and the experimental outputs. Repeating the original archive-to-tree comparison with `compare_history.py` or `inspect_sources.py` requires the externally supplied archives with the receipt digests. All 194 and 214 per-test outcomes can be inspected directly in this directory.
