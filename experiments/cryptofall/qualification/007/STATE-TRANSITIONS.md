# WT-CRYPTO-007 state-transition specification

## Objects and trust roots

All hashes are SHA-256 over the inherited canonical JSON encoding. The genesis digest identifies this disposable ledger and pins its starting hybrid policy, recovery and policy-witness roots, independent permit issuer, executor and four named replica identities. Each role has a distinct key. ML-DSA-65 signs ballots, permits, execution attestations and recovery controls using separately named domains. Both the effect owner and effect witness must supply Ed25519 and ML-DSA-65 signatures in hybrid mode. The prior verifier enforces the 30-second maximum claim and policy-transition lifetime. A positive decision has no effect outside the logical counter.

The abstract state is `(height, head, policy, gate, generation, value, requests, permits)`. Genesis starts at height, generation and value zero with empty request and spend maps. The certificate for a block comprises the block and signed, time-stamped votes over its digest and the genesis digest from distinct pinned members. The block covers its height, parent, command and derived receipt. Different signer subsets for an identical block identify the same history.

| Transition | Preconditions checked against the certified parent | Durable result |
|---|---|---|
| Vote | Correct next height and parent, valid command authorizations and derived receipt, local authority clock within claim or transition lifetime when applicable. | One SQLite transaction stores the full proposal, signed vote and digest in a unique height slot. The process replies after commit. Reopening a slot returns its original vote only for the exact block. |
| Commit | Three distinct valid votes for the same block, each independently verified in context. | This certificate defines one logical transition. Replicas install the certificate and full successor state together using a single SQLite transaction. Any valid certificate extending local state can be installed even if the replica voted for the losing branch. |
| Effect | Exact increment operation for specimen, current policy, owner and witness approvals, separate signed permit bound to ledger, policy, operation and evidence, current executor signature bound to parent and generation. Both request ID and permit must be unused. | Increment value by one, record the spend and the exact bound request, and install the COMMITTED receipt containing the resulting value. The quorum signatures cover all these fields. |
| Fence | Genuine bound permit, unused request and permit, recovery and policy-witness approvals for the exact binding and current parent. | Tombstone request and permit with a signed NOT_COMMITTED receipt. Value stays fixed. Delayed effect proposals for this request cannot advance that history. |
| Replace | Recovery and policy-witness approvals for the same genesis, parent, next generation and new distinct executor identity. | Advance generation and set executor. An old executor cannot issue an effect on the new parent. |
| Revoke or recover policy | Prior authenticated transition verifier checks the predecessor, epoch, monotonic revocations, time and authorized roles. Emergency recovery uses the independent ML-DSA recovery authority and policy witness. | Install new policy at a certified height. Votes on the old parent cannot be combined with votes on its successor. A revoked algorithm cannot authorize a fresh effect. Historical receipts remain reviewable at their voting times. |
| Exact recovery | Authenticated relay presents the original operation, evidence and signed permit. Surviving replicas return certified history and matching durable proposals and ballots. | The relay can assemble an existing QC and return its proof and receipt without voting or installing a block. A matching terminal receipt on an admissible history decides the request. |
| Ambiguous recovery | Too few valid votes, unknown request, mismatched disclosure, invalid proof, non-prefix certified histories, or failure to extend the independently retained floor. | UNRESOLVED. No permit release or increment follows. |

A floor is a separately kept pair of height and digest. The caller pins genesis independently and supplies its floor to review. Every furnished certified history must be a prefix of the longest and the longest must extend the floor. A missing response, a local log entry and an empty installed database are each insufficient for non-commitment. Historical exact decisions are terminal within the fault model. The interface does not certify the freshest head in an asynchronous network.

The offline reviewer separately reconstructs successors and receipts. It shares the canonical wire format, binding and key checks, and the inherited cryptographic authorization primitives with the implementation. It reads public input only. The matrix also contains observations of process termination and network reachability that require live replay.

## Installation crash observations

With a complete certificate held outside the process, the crash probe sent SIGKILL after the SQLite history insert and before the cached-state update. A separate SQLite connection observed zero increments, zero request entries, zero spends and zero certificate rows. After a second SIGKILL immediately following SQLite commit and before reply, an independent connection observed one of each. In both cases the restarted replica accepted the original certificate, and offline replay agreed with its state. These observations cover process death on this host. They do not measure power-loss behavior of independent storage controllers.
