# WT-GR risk taxonomy v1

These identifiers group review questions. They do not change engine rule IDs, emitted severities, CLI semantics or the supported scan surface. Static positive fixtures below yield REVIEW_REQUIRED / STATIC_REVIEW_SIGNAL. A covered negative yields NO_PATTERN_MATCH. Missing context or unsupported input yields INCONCLUSIVE where the original engine supports it. An unimplemented detector is NOT_TESTED. Behavioral pairs describe the expected observed fictional state. Passing the bounded experiment earns SYNTHETICALLY_VERIFIED only for that pair.

| ID and failure model | Supported input, method and reused implementation | Positive risk fixture / negative control and expected classification | Enforceable control and blast radius | Limits, independent check and deferred coverage |
|---|---|---|---|---|
| WT-GR-01. A test resets a protected database | Synthetic selector plus two SQLite memory handles. test_database_selection exercises an exact host allowlist. Static detector deferred | Protected or unknown selector is denied and both databases retain their rows. The approved fixture reset empties only the selected table | Separate database credentials, allowlisted test instance and operation. Potential loss of a whole database | Labels in Compose, migration SQL and safe environment templates can be misleading. Those formats are unqualified. Read both handles directly after each test |
| WT-GR-02. A session credential enters an agent-visible sink | Bounded JS/TS credential-to-sink rules WT-AGENT-003 and WT-EFFECT-002/005. Executed existing rule suites. No secret-value output | test_session_credential_explicit_browser_sinks vs test_redacted_and_non_sensitive_logging. Review a recognized token flow, allow the redacted control | Constrain the credential audience and lifetime, keep credential material outside context. Exposure can affect the principal's permitted resources | Mock loggers and unknown aliases limit static inference. test_sensitive_values_never_escape_interface checks emitted fields. Effective privileges and production token scope require external issuer evidence |
| WT-GR-03. Wrong cwd or link redirects a recursive deletion | Read-only POSIX target selection in capture_candidate. Canonical component walk from an opened root, no removal API. Shell parser deferred | Parent traversal, wildcard, root, link or absolute selection returns HOLD. An explicit regular file returns its fixture bytes | Require descriptor-relative confinement and independent approval of the resolved target. Loss can span the working tree | The exercise verifies selection alone. Compare in-root and external sentinel bytes. Actual recursive deletion, shell expansion and hostile mount races remain unqualified |
| WT-GR-04. Destructive authority can erase recovery evidence | Two logical stores and a limited resource-map retirement interface in test_backup_survives_limited_authority. Static IaC detection deferred | Attempt to retire the independent snapshot misses. Permitted fixture retirement removes the active entry and preserves original recovery bytes | Use a separately administered backup account and restrictive retention. Lost state can affect an entire environment | Same-UID file custody is synthetic. Read the witness independently. Terraform state exposure, cloud deletion, WORM retention and production restore remain untested |
| WT-GR-05. Written agent rules imply unsupported enforcement | Prompt document rules WT-PROMPT-001/003 plus S1 prose-source fixtures with a signed-grant gate. Executed static and synthetic profiles | Claimed priority is advisory. A recalled approval in AGENTS.md produces zero rows. Ordinary memory with two valid witnesses permits the exact approved row | Host owns authorization and interpreter restrictions. Unenforced rules expose every operation available to the agent | A warning can describe a policy example. Compare prose provenance with direct ledger observations. Missing host proof remains INCONCLUSIVE |
| WT-GR-06. Workflow or repository authority exceeds task scope | Static Actions workflow permissions in WT-GHA-004/005/006. No token or administrative operation exercised | Elevated downstream workflow plus artifact handoff in stage4_demo yields REVIEW_REQUIRED. Explicit narrow action_safe control yields NO_PATTERN_MATCH | Pin workflow source and restrict token and repository administration separately. Potential workflow, branch or repository damage | Defaults may be narrowed elsewhere. Verify actual protection and issuer scope independently. Force push, repository deletion/creation, organization settings and live scopes NOT_TESTED |
| WT-GR-07. A placeholder or missing capture is treated as local content | Local synthetic empty, missing, linked, nonlocal and fully present regular-file fixtures. Same bounded capture_candidate | Empty, missing, link and network-style path return HOLD. Complete file yields exact bytes | Require an explicitly selected complete source capture before acting. Synced deletion can propagate beyond one device | An empty legitimate file also holds. Read the external sentinel and actual bytes. Windows reparse points, provider metadata and sync propagation NOT_TESTED |
| WT-GR-08. Candidate MCP metadata widens permissions or borrows authority | Separately executed #13 tools/list baseline/candidate comparison, config and drift tests. Explicit operator-selected baseline. S1 covers forged tool approvals | #13 test_mcp uses authored drift and benign controls. S1 tool-response assertion fails signature validation and leaves an empty ledger | Pin server identity and consent outside transport, revalidate every effect. A shadowed tool can redirect a whole task | Historical module remains unintegrated. Read the baseline digest from trusted policy and replay with the original inputs. Static drift alone cannot verify runtime server identity, installer effects or consent |
| WT-GR-09. Untrusted PR material reaches privileged CI | Existing scan-build rules WT-GHA-001/002/005/006 on synthetic workflow YAML and cross-workflow artifacts. Static only | stage4_demo vs action_safe, plus test_workflow_run_artifact_trust_chain. REVIEW_REQUIRED vs NO_PATTERN_MATCH | Split privileged steps, pin handoffs and validate artifact identity. Potential write effects reach the repository or release pipeline | Platform defaults and repository settings alter effective rights. Independently check trigger, job permissions and artifact identity. Privileged execution and live exploitation NOT_TESTED |
| WT-GR-10. An agent bypasses a cooperative rule or auto-approves a tool | Existing bounded JS/TS, Python and shell rules WT-EFFECT-001/003/010. S1 tests prohibited proposals at host policy | test_independently_labelled_positive_patterns and benign suite controls. Flags produce review. Changed task is denied, authorized control commits one row | Keep policy outside the agent and deny unscoped requests. Exposure covers the agent's full tool set | Test examples can mention real flags. Shell alias resolution and sandbox escape detection are deferred. Check host authorization and ledger independently |
| WT-GR-11. Payment or message repeats, targets another recipient or uses the wrong amount | Synthetic transaction and message proposals, exact witnesses, host ceiling, unique slot and SQLite effect. S1 only | duplicate, concurrent, after-commit and lost-ack-wrong-recipient vs authorized and permitted-message. One exact durable row, incorrect reconciliation holds | Bind units, currency, destination, task and idempotency to both witnesses. Recheck limits at commit. Potential financial loss or unintended disclosure | Limit applies per operation. No aggregate balance or live transfer exists. Read exact ledger rows on a separate connection. An unavailable downstream query remains HOLD |
