# Pre-submission architecture decision

Retain the skills-only architecture for the review candidate. Keep the shipping decision blocked on GeoTrace and the remaining release gates. If one listing must eventually contain MCP, defer its first submission until that decision and partner eligibility are resolved.

| Dimension | Skills only | Skills plus local MCP |
|---|---|---|
| Installation and UX | The local marketplace installed the two skills into a disposable Codex CLI home. Users separately select an approved engine checkout and local inputs | A local process must start on each supported desktop. Tool discovery can present structured options. The host must separately establish which inputs and effects are authorized |
| Permissions and security | Five text/manifest members. No executable hook, server configuration or installer. The surrounding executor still controls filesystem access | Stdio exposes another process and its dependencies to untrusted requests. Isolate the process, pre-open allowed resources and place authorization and evidence verification outside it |
| Eligibility | Official guidance provides a skills-only flow. Local-executor metadata is present. Organization identity verification and listing approval remain unverified | Official guidance supports local MCP only for approved partners whose submitting organization is allowlisted. This account's allowlisting could not be established. Combined submission is BLOCKED |
| Compatibility and deployment | Tested on one Linux Codex CLI build. Local execution requires an available reviewed engine. Desktop, Windows and cloud-only behavior are NOT_TESTED | Stdio catalog prototype ran on Linux with installed MCP 1.29.0. Desktop packaging, client launch, OS sandbox and organization eligibility are NOT_TESTED |
| Upgrades and rollback | Version metadata/skills independently of the engine. Preserve the complete old ZIP, independently selected engine commit and receipt. A local removal/reinstall reproduced the reviewed bytes | Changes to tool permissions, schema, protocol and host enforcement need their own compatibility matrix. A later separate plugin has a distinct review/installation path |
| Review, testing and maintenance | Reproducible Git-blob packaging, package tests and exact engine fixture suite are available. Small dependency surface | Review the MCP dependency tree, schema drift, transport authentication, process boundaries, repair and rollback. A catalog test alone leaves all effect interfaces unqualified |

OpenAI's submission guidance says adding MCP to an already-submitted skills-only plugin is currently unsupported. The desktop-only guide requires partner approval for local MCP and specifies the local-executor manifest field for skills-only plugins. Hosted/public HTTPS MCP has a different review and deployment profile and is outside this offline design. The official pages were retrieved during this run and their text is retained in S0. ## Isolated prototype and integration contract

The local experimental commit af5b35f55926176e0ab928d53703ce1202eba554, tree 5549000ac29fbcfbfcf624632930a14da030dcd8, adds a stdio SDK server and test on a disposable worktree. S4/adapter.patch preserves the change. Its only tool, wolftrap_capabilities, takes an empty closed object and returns a fixed closed catalog including GeoTrace BLOCKED. The client performed protocol initialization, enumeration, a successful call and two rejected calls. It ran with external socket creation and connection syscalls intercepted. It is excluded from the development PR and package.

Future wolftrap_scan_authorized_local would accept a host-issued selection handle and a closed enum of qualified scan modes. wolftrap_verify_evidence would accept a host-selected evidence handle and independently supplied revision/policy pin. wolftrap_run_synthetic_challenge would accept only registered corpus IDs. Host-owned read-only descriptors, disjoint output storage, bounded arguments, a trusted policy generation and independent replay are prerequisites. Raw shell commands, arbitrary paths, repository mutation, network scanning and credential access have no interface. A compromised adapter could still lie about success or request another handle. Host policy and the effect/evidence witness must reject that independently. These three tools remain DESIGNED_OR_UNEXECUTED.

GeoTrace remains a required, separately selectable first-release capability. Recovery and qualification precede any catalog advertisement or proposed scan-geotrace / verify-geotrace interface. The prototype and ZIP confer no permission to infer identity or jurisdiction from location.
